# 디자인·제품 QA

## 유지한 시각 원칙

- 시작 화면은 짙은 남색 밤 풍경, 내부 화면은 종이 질감과 청록·녹슨 주황 포인트를 사용합니다.
- 각 화면의 상단 내비게이션, 3단계 흐름, 모바일 하단 내비게이션을 동일하게 유지합니다.
- 데이터가 없을 때도 카드 뼈대를 채우지 않고 전용 로딩·서비스키·빈 결과·장애 상태를 표시합니다.
- API 이미지가 없으면 특정 관광지처럼 보이는 대체 사진 대신 중립적인 밤하늘 플레이스홀더를 사용합니다.

## 실데이터 표시 규칙

- 관광지 이름·주소·좌표·이미지는 `KorService2` 응답만 표시합니다.
- 관광지 여유는 집중률 응답과 장소명이 일치할 때만 계산합니다.
- 캠핑장과 연관 관광지는 각각 해당 API 응답에서만 표시합니다.
- 현재 위치가 있을 때의 거리와 이동시간은 `직선거리 기반 참고 추정`으로 명확히 표시합니다.
- 구름량·주차대기·천문시각처럼 현재 연결 API가 제공하지 않는 값은 생성하지 않습니다.
- 각 추천 결과 아래에 서비스별 상태, 응답 건수, 조회시각을 노출합니다.

## 자동 검증

- TypeScript strict 타입 검사
- 공공데이터 키 누락·필수 파라미터·허용 목록·응답 정규화 테스트
- 실데이터 통합 추천과 더미 미생성 테스트
- SPA 정적 라우팅과 모듈형 Worker 패키징 테스트
- 프로덕션 빌드

## 실제 키 연결 후 확인할 항목

1. `/api/health`의 `publicDataConfigured: true`
2. 서비스별 승인 상태와 `sources[].status`
3. 관광지명 기준 집중률 결합률
4. API 원본 이미지의 저작권·공공누리 유형
5. 데스크톱·모바일에서 긴 관광지명과 주소 줄바꿈
